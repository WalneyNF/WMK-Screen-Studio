Manual da API — WMK Audience Intelligence

API REST local, gratuita, com SQLite e Python, para reunir perguntas de lives, analisar assuntos e fornecer dados a aplicações de marketing e relatórios de reuniões.

README · Roadmap · Protótipo no navegador

1. Estado atual e arquitetura

Implementado no código-fonte: importação CSV/TSV/JSON por linha de comando, SQLite, classificação heurística, estatísticas, sugestões simples, API REST de leitura com chave e relatório HTML com gráficos. Não implementado: coleta automática do YouTube, controle de permissões por funcionário, IA conectada, painel integrado ao Tauri e publicação segura na internet. A compilação e os testes precisam ser verificados antes de anunciar uma versão estável.

A API fornece dados importados, não estatísticas oficiais de alcance, visualizações ou inscritos do YouTube. Sem um dataset real não é possível afirmar a popularidade de temas do canal.

2. Requisitos

Python 3.10 ou superior com SQLite da biblioteca padrão. Não é necessário usar pip install, contratar IA ou ter uma conta em nuvem.

git clone https://github.com/WalneyNF/WMK-Screen-Studio.git
cd WMK-Screen-Studio
py -3 tools\audience_api.py --help

Se o repositório já existe no computador, execute git pull nele em vez de cloná-lo novamente.

3. Exemplo de chat em CSV

Crie meu-chat.csv com codificação UTF-8. Use as colunas autor, mensagem, data. Somente a mensagem é essencial.

autor;mensagem;data
Ana;Como configurar o microfone?;2026-11-13T20:05:00
Carlos;Gostei da transmissão!;2026-11-13T20:06:00
Pedro;Quando terá outra live?;2026-11-13T20:07:00

JSON também é aceito:

{
  "messages": [
    {"author":"Ana","message":"Como configurar a webcam?"},
    {"author":"Pedro","message":"Tem tutorial de exportação?"}
  ]
}

Os registros devem ser importados a partir de arquivos obtidos de forma autorizada. O YouTube não oferece por sua API oficial uma recuperação irrestrita de chats depois da transmissão encerrada.

4. Importar uma live

py -3 tools\audience_api.py import --title "Live de exemplo" --file meu-chat.csv

A resposta contém live_id e quantidade de mensagens. Os dados ficam, por padrão, em tools/data/audience.sqlite3. Esse arquivo pode conter dados pessoais: mantenha-o fora do GitHub e faça cópias de segurança protegidas.

5. Iniciar API com chave própria

Abra PowerShell na pasta do projeto:

$env:WMK_AUDIENCE_API_KEY = py -3 -c "import secrets;print(secrets.token_urlsafe(36))"
py -3 tools\audience_api.py serve --port 8767

Endereço padrão: http://127.0.0.1:8767. É obrigatório configurar chave com pelo menos 24 caracteres. Também é possível usar --key-file com arquivo privado.

Proteção: nesta versão a API aceita conexões somente do próprio computador. Não abra a porta diretamente na internet. Para diretorias e outras máquinas, será necessária uma etapa posterior com HTTPS, autenticação individual, permissões por perfil, auditoria e política de retenção. Não compartilhe chaves de API com usuários não autorizados.

6. Consultas e exemplos

No mesmo PowerShell que contém a chave, ou em outro que tenha sido configurado de maneira segura:

$headers = @{ "X-API-Key" = $env:WMK_AUDIENCE_API_KEY }
Invoke-RestMethod http://127.0.0.1:8767/health
Invoke-RestMethod http://127.0.0.1:8767/v1/lives -Headers $headers
Invoke-RestMethod http://127.0.0.1:8767/v1/lives/1/summary -Headers $headers
Invoke-RestMethod http://127.0.0.1:8767/v1/lives/1/topics -Headers $headers
Invoke-RestMethod http://127.0.0.1:8767/v1/lives/1/questions?limit=50 -Headers $headers
Invoke-RestMethod http://127.0.0.1:8767/v1/lives/1/suggestions -Headers $headers
GETObjetivoChave?
/healthEstado do serviçoNão
/v1/livesListagem das lives importadasSim
/v1/lives/{id}/summaryMensagens, autores, perguntas, temasSim
/v1/lives/{id}/topicsFrequência de temasSim
/v1/lives/{id}/messagesMensagens paginadasSim
/v1/lives/{id}/questionsPossíveis perguntas paginadasSim
/v1/lives/{id}/suggestionsSugestões por regrasSim
/v1/lives/{id}/report.htmlHTML com gráficos de barrasSim

Listagens de mensagens aceitam ?limit=50&offset=0, limite máximo de 200 por chamada. Esta API é somente leitura: importar dados exige comando local.

7. Relatório HTML offline para reuniões

Para gerar um relatório que pode ser aberto sem API nem internet:

py -3 tools\audience_api.py export --live 1 --out relatorios\reuniao.html

Abra relatorios\reuniao.html no navegador. O documento contém métricas e gráficos de barras de assuntos. O comando usa dados da live de identificador 1; substitua pelo ID real. Evite compartilhar relatos individuais ou dados pessoais além do necessário.

8. Testes automáticos

py -3 -m unittest discover -s tests -p test_audience_api.py -v

Os testes verificam classificação inicial, importação, duplicatas, totalização, escape de HTML e geração de sugestões. Testes de integração com redes externas, autorização por usuário e testes no aplicativo Tauri ainda são pendentes.

9. IA é opcional e escolhida pelo usuário

O programa não exige ChatGPT, OpenAI ou outro serviço. Futuramente, no cadastro de provedores, cada pessoa informará suas próprias credenciais, escolherá o modelo e configurará seu limite de consumo. As credenciais não devem ser incluídas nos arquivos JSON exportados nem em relatórios. Antes de enviar textos de espectadores à nuvem, o usuário deverá revisar e autorizar os dados enviados.

As sugestões atuais são heurísticas: não são respostas produzidas por IA nem métricas de engajamento de toda a plataforma.
