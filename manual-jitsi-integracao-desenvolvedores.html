WMK Meeting Studio — manual de implantação e extensões

Da primeira sala Jitsi à integração React, autenticação, WebRTC, aulas e IA por participante. Conteúdo para iniciantes e programadores que desejam ampliar um projeto livre.

Abrir protótipo funcional de salas · Jitsi explicado do zero · Guia de servidores · Plano Classroom

1. Entenda o que está pronto

Publicado: a página HTML wmk-meeting-studio.html para criar nomes de salas, gerar e compartilhar convites, abrir a reunião no serviço Jitsi escolhido e, se a API estiver disponível, incorporar o Jitsi na página. Layout responsivo para celulares.

Não publicado como pronto: servidor próprio instalado, autenticação e controle de professor/aluno, sincronização de quadro branco, gravação, sistema de exercícios, IA pessoal conectada, API de backend e composição de convidados na transmissão. A página é uma interface de entrada e teste, não um substituto do Jitsi.

O serviço meet.jit.si serve para testes e uso público nas condições do provedor, mas não é recomendado pela documentação oficial para embutir em uma aplicação de produção. Planeje servidor autogerenciado ou serviço comercial apropriado para clientes reais.

2. Primeiro uso, sem instalar servidor

  1. Abra WMK Meeting Studio num navegador moderno, de preferência via HTTPS.
  2. Mantenha https://meet.jit.si no campo Servidor.
  3. Pressione Criar nome aleatório (ou digite um identificador com pelo menos oito caracteres).
  4. Pressione Preparar convite e Copiar link.
  5. Envie ao aluno pelo WhatsApp, e-mail ou outra ferramenta de sua escolha.
  6. Entre em Abrir reunião em nova aba. O organizador pode precisar autenticar-se no servidor público.
  7. Teste com outro participante em rede diferente, especialmente um celular em dados móveis.

O botão de incorporação é opcional. Se o navegador ou o servidor impedir, continue pela nova aba. A página não verifica se a sala está reservada ou se o participante foi autenticado.

O Jitsi Meet cuida de chamada de vídeo, áudio e ferramentas nativas da conferência. O WMK cuida da experiência própria, atividades educacionais e integrações. A autenticação e o papel de moderador devem ser aplicados pelo servidor; escondê-los no CSS não oferece segurança.

4. Código mínimo de incorporação

Exemplo oficial simplificado. Não execute esse trecho em uma página de outro domínio sem HTTPS e configuração de permissões. Para uma instalação própria, substitua meet.jit.si pelo domínio real do seu servidor.

<div id="sala" style="height:600px"></div>
<script src="https://meet.jit.si/external_api.js"></script>
<script>
const api = new JitsiMeetExternalAPI("meet.jit.si", {
  roomName: "wmk-exemplo-sala-123456",
  width: "100%",
  height: "100%",
  parentNode: document.getElementById("sala"),
  lang: "ptBR"
});
// Ao sair da página/desmontar o componente:
window.addEventListener("beforeunload", () => api.dispose());
</script>

Documentação oficial: IFrame API. A política do provedor pode alterar o comportamento em celulares, autenticação e incorporação.

5. Exemplo React / Tauri

O WMK Desktop utiliza React. O componente deve criar a sessão quando a sala for exibida e destruí-la quando o usuário sair, evitando câmeras/microfones presos em instâncias antigas.

import { useEffect, useRef } from "react";
declare global {
  interface Window {
    JitsiMeetExternalAPI?: new (
      domain: string, opts: Record<string, unknown>
    ) => { dispose(): void };
  }
}
export function Sala({ dominio, nome }: {
  dominio: string; nome: string;
}) {
  const mount = useRef<HTMLDivElement>(null);
  useEffect(() => {
    // Carregue external_api.js pelo domínio HTTPS autorizado,
    // verificando disponibilidade e tratando falhas antes daqui.
    if (!mount.current || !window.JitsiMeetExternalAPI) return;
    const api = new window.JitsiMeetExternalAPI(dominio, {
      roomName: nome, width: "100%", height: "100%",
      parentNode: mount.current,
    });
    return () => api.dispose();
  }, [dominio, nome]);
  return <div ref={mount} style={{ height: "75vh" }} />;
}

Para Tauri, além do código React, revisar permissões de WebView, Content Security Policy, URLs autorizadas, comportamento de captura de mídia e diferenças entre Windows, Linux, macOS e navegadores. Em alguns casos, é preferível abrir no navegador externo do usuário.

6. Servidor próprio: quando e como?

Para produção, normalmente você terá um VPS Linux ou servidor administrado, um domínio e certificados HTTPS. O Jitsi oferece instalação via Docker e pacotes de Linux. A instalação inclui frontend web, XMPP/Prosody, Jicofo e Jitsi Videobridge. JVB distribui áudio/vídeo em reuniões multipessoa.

  1. Planeje quantidade simultânea de usuários e capacidade de rede.
  2. Escolha VPS Linux com IP público e domínio, configurando registro DNS A.
  3. Instale Docker Engine + Compose e extraia release estável do docker-jitsi-meet.
  4. Configure .env, URL pública, HTTPS e senhas geradas pelo script oficial da release.
  5. Verifique TCP 443 e mídia UDP 10000 (padrões usuais); configure TURN caso as redes precisem.
  6. Ative autenticação, políticas de salas e monitoramento.
  7. Teste em duas redes distintas e sob carga real. Monitore perda de pacotes e uso do servidor.

Manual oficial Docker e explicação WMK passo a passo. Instalar software gratuito não elimina custos de tráfego e hospedagem.

7. Sala de aula, IA pessoal e isolamento

Planejamento de contas: um usuário possui suas próprias preferências de provedor e modelo de IA; um professor pode publicar um material ou tarefa, enquanto um aluno utiliza tutor pessoal em conversa privada. Compartilhar respostas com o grupo é sempre uma decisão explícita.

PeçaImplementação recomendada
LoginBackend com identidade própria e sessões curtas; nunca somente nome digitado na página
PermissõesProfessor/moderador/aluno aplicados pelo backend e servidor de conferência
IA por usuárioProvedor configurável; chaves armazenadas de forma segura no servidor ou vault do dispositivo
ExercíciosQuestionários em JSON validados pelo backend, com trilha de correções
TranscriçãoWhisper local ou servidor configurado, consentimento e separação por sala
ExportaçãoArquivos autorizados, sem expor dados pessoais de outras turmas

Uma IA não deve assumir que um cálculo estrutural, diagnóstico clínico ou parecer jurídico está correto. Nessas áreas, exigir validação por especialistas competentes e registrar fontes.

8. Ideias para programadores ampliarem

  1. QR Code de convite: gerar código localmente com biblioteca de licença compatível.
  2. Painel de professor: lista de mão levantada, objetivos da aula e controle de exercícios.
  3. Quadro branco: eventos sincronizados com permissões, versões e histórico.
  4. Grupos de trabalho: salas menores com convites temporários e retorno à principal.
  5. Modo internet lenta: áudio prioritário e redução de vídeo.
  6. IA individual: tutoria por pistas e revisão orientada, com controle de custos.
  7. Catálogo de aulas: gravações com legendas e capítulos, mediante autorização.
  8. Integração com WMK Video Composer: adicionar fonte de vídeo remota mediante arquitetura específica; iframe sozinho não é uma faixa de mídia exportável.
  9. API para sistemas escolares: endpoints autenticados, isolamento por organização e trilha de auditoria.
  10. Exportação de relatórios: frequência confirmada por interação/participação registrada, sem inferir aprendizagem pelo tempo de câmera ligada.

9. Segurança: lista obrigatória antes de produção

  • Usar HTTPS; validar domínios dos servidores autorizados e limitar embed a origens confiáveis.
  • Nunca colocar segredo JWT, senha de administrador ou chave de IA em HTML/JavaScript entregue ao cliente.
  • Autenticação e autorização verificadas no servidor, inclusive separação por organização/turma.
  • Salas com nomes aleatórios, mas tratar convite como identificador, não credencial de segurança.
  • Configurar lobby, moderação, controles de gravação e limites de uso; avisar quando houver gravação.
  • Tratar mensagens e prompts de participantes como dados não confiáveis, sem executar instruções recebidas.
  • Manter software e dependências atualizados, registrar incidentes e realizar testes de restauração de backups.
  • Para menores, aplicar proteção reforçada de dados, supervisão e moderação, conforme normas pertinentes.

Tradução simultânea: legendas e áudio

O WMK Meeting Studio oferece um painel experimental Legendas e tradução que solicita ações da IFrame API (toggleSubtitles, setSubtitles) e permite selecionar um idioma. Não se deve prometer tradução instantânea apenas pela presença do botão.

  1. Instale e configure um serviço de transcrição compatível com sua versão do Jitsi. Verifique a documentação de transcrição do Jitsi e os modelos/idiomas suportados.
  2. Habilite transcription.enabled na configuração do frontend. Configure o mecanismo de reconhecimento e teste frases simples antes de habilitar tradução.
  3. Se desejar tradução de texto, configure um tradutor compatível, as credenciais e os idiomas aceitos no servidor. A transcrição e a tradução podem ter custos de infraestrutura ou API.
  4. Na reunião, o participante ativa legendas e seleciona seu idioma. Teste com falas em português, inglês e espanhol, comparando texto original e tradução.
  5. Não confunda tradução escrita com tradução de áudio: esta requer serviço específico, consentimento e maior capacidade de processamento.

O controle WMK envia preferências à API; não detecta por si só se uma tradução aconteceu. Confirme na interface do Jitsi e em testes reais. Considere consentimento dos participantes, retenção e eventual envio de voz/texto a provedores externos.

Referência oficial: Jitsi — transcrição e tradução e Comandos IFrame API.
